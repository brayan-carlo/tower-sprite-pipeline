# Tower Sprite Pipeline

## Purpose

Create one action in one orientation from a supplied isolated PNG. A natural request activates the skill; `$tower-sprite-pipeline` is optional. Keep outputs outside the game project. Technical assembly requires agent visual review before delivery; user acceptance and Unity validation remain separate.

## Route

- For an explicit native/no-fal biped walk or planted attack left or right, with authorization covering local motion construction, read [native-articulated-workflow.md](references/native-articulated-workflow.md). It supports eight frames built from native/source art and local articulation, followed by artifact-bound review and export. Preserving dimensions alone does not justify replacing a whole-body attack with an isolated arm swing. The agent prepares layers and evidence from the user's PNG; a prepared sheet is not required. The attack profile requires both feet planted and one strike followed by recovery; it does not cover lunges, jumps or quadruped attacks.
- For an explicit native/no-fal lateral pixel-art quadruped run, with authorization covering native pose construction and local assembly, read [native-sprite-sheet-workflow.md](references/native-sprite-sheet-workflow.md). This native facade supports eight frames and two four-phase strides. Keep an explicit fal choice on fal. Unsupported native actions/views require an honest limitation; never silently call fal in a no-fal task or use the quadruped profile for a biped.
- For other new isolated PNG animations, read [generic-sprite-sheet-workflow.md](references/generic-sprite-sheet-workflow.md) and use the v3 fal facade. Reuse the supplied image and explicit context. For animation inputs, ask only for a missing action or orientation; ask for the source only when no single supplied image can be identified. State defaults as information, not as a form. Resolve a genuinely missing authorization only as described below. Keeping fal available alone does not authorize paid fallback in a native-only task.
- For an existing manifest, inspect its mode/schema before choosing a contract. `native_articulated_workflow_v1` uses the articulated workflow; `native_sheet_v1` uses the quadruped native workflow. After complete native PASS, a new scope with the body-alignment policy must use the alignment adapter and review its returned v3 child as described below. Never fabricate a fal ledger for either native parent. A v3 `whole_sheet` manifest stays on the v3 workflow. A `generic_sequential` manifest stays on [generic-png-sequential-contract.md](references/generic-png-sequential-contract.md). A `sequential_reconstruction` manifest stays on [sequential-reconstruction-contract.md](references/sequential-reconstruction-contract.md). Other deterministic or hybrid legacy manifests stay on [art-contract.md](references/art-contract.md) and [sprite-run-contract.md](references/sprite-run-contract.md).
- For an explicit request to use the legacy generic sequential contract, also read [generic-png-sequential-contract.md](references/generic-png-sequential-contract.md). Preserve its original fields, approval gates, states and stop-at-rejected-frame behavior. Do not apply those requirements to a new v3 request.

Permission to clean alpha edges covers that correction only. Permission to center the body covers X-only translation only. Neither authorizes reconstructing motion or switching a requested fal video to local articulation. For a new request without an explicit native/no-fal choice, use the generic route; limited local cleanup permission does not change that selection. Reuse a prior explicit construction authorization only within its stated scope.

The request and its current-session authorization cover the bounded operation. Reuse them for live price refresh, a known-ID resume and an in-scope bounded revision; do not ask for the same permission again. New managed generation uses [task-budget-and-corrections.md](references/task-budget-and-corrections.md): the agent resolves the shared task, keeps prior exposure/attempts and provides its real context to the facade. A new run or prompt does not reset the budget. Never ask the user for a guide, task/run ID, request JSON, interpreter path, backend choice, or the legacy five-field form for a new v3 request.

## Runtime and secrets

Resolve an `intérprete Python 3 real` with `Pillow`, Node 22 or newer, and external FFmpeg for video. In Codex, use `load_workspace_dependencies`; on Windows, also inspect the bundled `codex-primary-runtime` and available external FFmpeg. Use Python with `-B` and `PYTHONDONTWRITEBYTECODE=1`. Do not install dependencies inside the skill and, if the required runtime is genuinely absent, `no crear un compositor ni una implementación alternativa`.

The native route needs Python/Pillow and the native image tool; it does not need Node, FFmpeg or `FAL_KEY`. Generation is not offline. Python image edits require explicit user authorization, reused throughout the authorized scope. First check the current request and earlier authorization: explicit permission for local X-only alignment or alpha cleanup already covers that operation; do not ask again. If that permission is genuinely absent, ask once for the specific local operation before performing it. Merely stating a default, or permission for provider generation, does not establish permission for Python edits. Continue independent preparation while waiting; do not reopen the known animation inputs or cap. This narrow authorization requirement is separate from the prohibition on asking the user to fill technical forms.

For the fal route only, let the facade resolve `FAL_KEY` from the Process environment and then the Windows User environment. Never request or expose its value in chat, command arguments, configuration, receipts, state, or reports. When source, action, orientation and shared task context are resolved but no verified fal run manifest exists, call `generate` once even if the key is known to be absent. If it returns `KEY_SETUP_REQUIRED` / `FAL_KEY_MISSING` with a real `run_manifest`, preserve that exact path, give secure environment-variable setup instructions, and use `resume` on it after setup. Never invent a manifest or call `resume` without a verified path; if setup finishes before any run exists, start with `generate` using that task context.

## Outcome

For new scopes, keep the body horizontally centered while preserving natural vertical bounce. Read [body-alignment.md](references/body-alignment.md): annotate a homologous body point, create the offline X-only derivative, then review that new artifact set. The body point excludes weapons, tails and moving extremities. New native candidates must first pass their complete native review, yielding `READY_FOR_ALIGNMENT`; the child still needs its own v3 review. New v3 PASS/export requires the bound alignment proof and a finding for every frame; silhouette centering and equal canvas sizes do not satisfy it. The agent handles coordinates and evidence, not the user. Historical scopes keep their stored policy and approvals.

For new native runs, annotate two visible source anatomical lengths and the body/export pivot before generation. Follow the profile's geometry contract: the quadruped route uses `READY_FOR_GEOMETRY_REVIEW` after ingest; the articulated biped route validates source geometry during build and output geometry with its complete visual review. Inspect all eight frames, the same anatomical lengths, actual support points and every secondary component. Preserve one source-based scale and shared output pivot; expand transparent margins when needed. The agent handles these details from the PNG; the user flow remains PNG + action + direction + duration.

Before a paid generation/edit reuses a generated guide, inspect the actual guide properties the next prompt asks to preserve. Compare anatomy, body/equipment scale and attachment ownership with the original supplied character. If the full view is downscaled or a connection is ambiguous, inspect native-resolution joint/attachment crops before submitting. The original is authoritative for character-specific anatomy, including nonhuman limb counts. Correct or exclude a mismatching guide property from preservation constraints; never freeze a known defect because the requested edit concerns only material. Retain concrete comparison findings within the existing authorization, shared budget and route.

On `READY_FOR_VISUAL_REVIEW`, inspect the source, sheet, all frames and GIF. Record the artifact-bound visual review using the reference's `review` command. Compare stable anatomical anchors (such as head and torso), including the last-to-first transition. Silhouette-area flags require explicit findings; equal canvas dimensions, a shared resize factor or no flags do not prove consistent character size.

For native action planning and review, read [native-motion-review.md](references/native-motion-review.md). Validate opposite key poses before spending on intermediates. Held equipment requires explicit hand/grip attachment, rigidity and cyclic trajectory evidence; general notes saying "smooth motion" are insufficient. These are agent review requirements; the diagnostic helper measures annotated pixels and does not grant automatic approval.

A confirmed change in character size/proportions, wrong direction, clipping or broken action/loop is a failed check: record `VISUAL_REJECTED`. Do not deliver a known defective sheet/GIF as the completed result with a disclaimer, nor fix scale by blindly equalizing silhouette heights. Retained artifacts may be shown only as explicitly rejected diagnostic evidence. A rejected run requires correction within existing authorization or an honest blocked outcome.

Only `READY_FOR_DELIVERY` with `delivery_allowed: true` permits `export`. Deliver the verified export with concrete agent findings. The agent performs this review without asking the user to approve technical quality. It does not establish user acceptance, actual billing or Unity readiness.

Keep `SUBMISSION_STATUS_UNKNOWN` non-resubmittable. Same-manifest managed recovery may discover an ID that became durable in Node after the facade recorded UNKNOWN; the existing marker still prevents another POST. Without a recoverable ID, preserve uncertainty. Resume known pending requests through their recorded identity. A terminal cycle-quality rejection may use `revise` with concrete feedback and its structured correction while the shared cap and strategy limit allow it; never revise unknown or pending work. Technical cycle evidence is not an invented artistic failure.
