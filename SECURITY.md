# Security and sensitive data

Never post API keys, tokens, private source images, account details, or raw provider receipts in an issue or pull request.

If a credential was exposed, revoke or rotate it with the issuing service. Deleting the visible text is not sufficient to invalidate a copied credential.

For a security problem, use GitHub's private vulnerability reporting option if it is available for this repository. If no private channel is available, ask the maintainer for one without posting exploit details, secrets, or sensitive attachments.

Ordinary offline checks should not require a real FAL credential. Paid integration work must be deliberate and use a separately authorized budget.
