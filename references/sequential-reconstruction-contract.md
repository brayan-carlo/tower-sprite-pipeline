# Sequential Reconstruction Contract

Read this file only when the manifest has `mode: sequential_reconstruction`.
The canonical pilot is `assets/pilots/ogre_walk_s_8f.json`; do not substitute
the deterministic six-frame manifest or its models, dimensions, budget or
attempt policy.

## Contract values

The validator requires the approved manifest shape and values, including:

- eight RGBA frames, each `256x416`, with `technical_scale: 2` (`512x832` for
  generation references);
- `bottom-center` anchor and `root_motion: false`;
- primary `fal-ai/qwen-image-2/edit`, fallback
  `fal-ai/nano-banana-2/edit`, and `max_budget_usd: 0.50`;
- `max_primary_submits: 10` and `max_fallback_submits: 2`;
- pose order `left_contact`, `left_down`, `left_pass`, `left_up`,
  `right_contact`, `right_down`, `right_pass`, `right_up`;
- the declared `identity_regions`, `foot_regions` and `qa` object. Do not add
  defaults for missing dimensions, poses, models, anchors or budget.

The source is normalized into the external run. Generation references are
ordered as `master`, optional `previous_accepted`, then `pose`. Frame 1 uses
`master, pose`; later frames require the immediately preceding frame to be
`ACCEPTED` and use `master, previous_accepted, pose`. A `REJECTED` frame stays
in the current slot, never becomes a continuity reference and cannot advance
the chain.

## External run layout

Use a new run outside the Unity project. `prepare` creates and confines:

```text
input/master/
input/pose-guides/
input/references/
raw/
normalized/frames/
previews/
reports/
```

The authoritative run record is `reports/run_manifest.json`; the prepared-run
marker is `reports/prepared-run.json`. Request JSON must be written below
`input/references/`. Never reuse a run ID, write below `Assets/`, or follow a
link/junction outside the run.

## Python CLI

Resolve `$python` to a real Python 3 runtime with Pillow and `$externalRoot`
to a directory outside the project. The CLI is
`scripts/sequential_reconstruction.py` and exposes exactly these commands:

```powershell
& $python scripts/sequential_reconstruction.py validate `
  --manifest assets/pilots/ogre_walk_s_8f.json

& $python scripts/sequential_reconstruction.py prepare `
  --manifest assets/pilots/ogre_walk_s_8f.json `
  --workspace-root $externalRoot --run-id $runId

& $python scripts/sequential_reconstruction.py next-request `
  --manifest assets/pilots/ogre_walk_s_8f.json `
  --run-manifest $runManifest `
  --request-output $runDir/input/references/frame-01-request.json

& $python scripts/sequential_reconstruction.py resume `
  --manifest assets/pilots/ogre_walk_s_8f.json `
  --run-manifest $runManifest `
  --request-output $runDir/input/references/frame-01-request.json

& $python scripts/sequential_reconstruction.py evaluate `
  --run-manifest $runManifest --frame-index $frameIndex --raw $rawResult

& $python scripts/sequential_reconstruction.py assemble `
  --manifest assets/pilots/ogre_walk_s_8f.json --run-manifest $runManifest
```

The backtick line continuations are PowerShell syntax; the flags above are the
complete argparse interfaces. `resume` has the same request-building behavior
as `next-request`; it does not submit or invent a new request. `validate`
returns `VALID` or `BLOCKED`; `prepare` returns `DRAFT` and the run paths.

`next-request` and `resume` return `request_ready: true` with `frame_index`,
`model`, `reference_roles`, `reference_paths` and `request_output`, or return
`request_ready: false` with `reason: NO_NEW_REQUEST` (or the persisted terminal
reason). The generated request file has exactly this top-level shape:

```json
{
  "frame_index": 1,
  "model": "fal-ai/qwen-image-2/edit",
  "input": {},
  "request_fingerprint": "<canonical-payload-sha256>"
}
```

The non-empty `input` is generated by the CLI and contains `image_urls`,
`image_size: {"width": 512, "height": 832}`, `num_images: 1`,
`output_format: "png"`, `enable_prompt_expansion: false`, a deterministic
`seed`, `prompt` and `negative_prompt`. Fallback requests additionally carry
`resolution: "0.5K"`. The CLI persists the same fingerprint, frame and model
under `run_manifest.next_request`; the transport requires that exact current
handoff. Do not add credentials, request IDs or other top-level fields to this
transport JSON.

The prompt names the prepared run chroma exactly as a solid uniform background
using both decimal and hexadecimal notation, for example
`RGB(255, 0, 255)/#FF00FF, no gradient`. The value is derived from
`run_manifest.chroma_rgb`, not from a fixed prompt constant. Because the prompt
is inside `input`, any chroma change also changes the canonical request
fingerprint.

## Request and evaluation order

For each frame, request selection is Qwen-first, follows the manifest's global
primary/fallback caps and stops with `TECHNICAL_REJECTED` plus
`ATTEMPT_POLICY_EXHAUSTED` when no permitted model remains. An active request,
or a completed request without a result path, is handled by the transport
before another submit. A completed result with a path must be evaluated before
the frame can be requested again.

After a completed result is saved under `raw/frame-XX/`, run `evaluate` for the
current first-unaccepted frame. The result is persisted as
`reports/frame-XX-qa.json`; accepted frames also produce normalized and
technical copies. Evaluation requires a persisted completed request whose
`result_path` and `result_sha256` match the supplied raw path and bytes. Its
`request_fingerprint` must be lowercase 64-hex and must equal the exact current
`run_manifest.next_request` handoff for the same frame and model; absent,
malformed or stale fingerprints block before any report or normalized file is
written. Each attempt records request ID, fingerprint, attempt number, model,
raw/result hash and its evaluation. The accepted report also records SHA-256,
path and actual dimensions for raw plus fixed normalized (`256x416`) and
technical (`512x832`) artifacts. Qwen raw PNGs must be exactly `512x832`.
Fallback Nano `0.5K` raw PNGs may use a model-native size only when width and
height are at least `256x416` and the aspect is exactly compatible, checked as
`width * 416 == height * 256`; this permits `400x650` without upscaling. The
decoded format must be PNG regardless of file extension. Qwen size mismatch,
Nano wrong aspect, Nano dimensions below the final frame, non-PNG or unreadable
bytes remain blocked before a report is written. Valid raw is alpha-recovered
at its native size and resized directly to `256x416`; accepted technical output
remains `512x832`. Evaluation
rejects missing, pending, out-of-order or conflicting evaluations without
silently advancing the chain.

`EMPTY_ALPHA` and `NORMALIZED_SUBJECT_OUT_OF_BOUNDS` are generated-content
normalization failures. For a provenance-valid `COMPLETED` request they are
persisted as a frame `REJECTED` report and attempt with the exact failure code,
request fingerprint/ID, result/raw SHA-256, and all five QA groups failing
closed. Their normalized and technical provenance paths and hashes are null,
and no normalized or technical files are written. This keeps the frame current
so `next-request` can select the next retry allowed by policy. Missing or
invalid chroma configuration, raw dimension mismatch, unreadable raw bytes and
all confinement/provenance errors remain `BLOCKED` and produce no frame QA
report.

Frame QA returns `ACCEPTED` or `REJECTED`. `checks` contains exactly the five
groups `geometry`, `identity`, `palette`, `alpha_components` and `feet`; every
group has its own machine-readable `failures`. The checks include geometry and
ground row 415, alpha, area/bbox stability, palette, connected components,
master/previous identity regions, foot connectivity and planted-foot drift.
The planted foot limit is 2 normalized pixels; the manifest also controls the
new-foot-island limit. Rejected raw results remain available for audit but are
never normalized as accepted references.

## Node transport and preflight

For an explicitly authorized real transport, use the existing external Node
wrapper and dependency directory. The wrapper accepts exactly these flags:

```powershell
& $node scripts/fal_sequential_generate.mjs `
  --manifest $manifest `
  --run-manifest $runManifest `
  --pricing $pricing `
  --request-input $requestInput `
  --client-module $externalClientModule
```

`--client-module` may be omitted only when the external Node environment
already provides `@fal-ai/client`; never install beside the skill or in Unity.
The request input must contain only `frame_index`, `model`, `input` and
`request_fingerprint`, use the exact nested input schema, use one of the two
manifest models, and use `0.5K` only for Nano requests.

Before importing the client or submitting, transport validation requires:

1. the complete literal sequential manifest and a prepared, confined run whose
   normalized manifest and source match the project;
2. a non-terminal sequential chain with no accepted-frame replay and no
   completed result awaiting `evaluate`;
3. a non-empty `FAL_KEY` in the environment (never in arguments, files or
   output);
4. for a new submit, fresh authenticated pricing evidence, the exact current
   fingerprinted request, matching first-unaccepted frame/recovery model and a
   remaining worst-case estimate within the cap.

If any preflight check fails, the Node transport performs no client import or
submit. The Python request file is already the explicit handoff artifact; the
Node wrapper never rewrites it. An active request ID, or a `COMPLETED` ID still
without `result_path`, is queried/recovered before pricing, budget and request
input gates that apply only to a new submit. A submit invocation creates at
most one new request. A timeout or
malformed submission
without an ID is persisted as `SUBMISSION_STATUS_UNKNOWN` and is never
resent automatically. Completed results are fetched before another submit;
permanent validation failures retain only a safe error type.

`safe_error_type` is restricted to the local categories `AbortError`,
`InvalidSubmissionResponse`, `NetworkError`, `RESULT_VALIDATION_ERROR`,
`SubmitError`, `TimeoutError` and `image_too_small`. Client/server strings are
never copied verbatim unless they are one of those categories, and any category
that equals, contains or is contained by the active `FAL_KEY` is omitted.

## States and reason codes

Request statuses persisted by transport are `IN_QUEUE`, `IN_PROGRESS`,
`COMPLETED`, `FAILED`, `CANCELLED` and `SUBMISSION_STATUS_UNKNOWN`.

The Python run states are `DRAFT`, `TECHNICAL_REJECTED` and
`READY_FOR_VISUAL_REVIEW`; transport blocks report `BLOCKED`. Important
machine-readable reasons include:

| Stage | Exact reasons |
|---|---|
| Routing and confinement | `INVALID_MANIFEST`, `INVALID_RUN_MANIFEST`, `WORKSPACE_INSIDE_PROJECT`, `RUN_OUTSIDE_WORKSPACE`, `RUN_ALREADY_EXISTS`, `REQUEST_OUTPUT_NOT_CONFINED`, `WORKSPACE_CONFINEMENT_FAILED` |
| Chain and requests | `NO_ACCEPTED_PREDECESSOR`, `INVALID_FRAME_CHAIN`, `NO_NEW_REQUEST`, `ATTEMPT_POLICY_EXHAUSTED`, `RUN_TERMINAL`, `EVALUATION_REQUIRED`, `EVALUATION_REQUEST_NOT_FOUND`, `EVALUATION_REQUEST_NOT_COMPLETED`, `FRAME_OUT_OF_ORDER`, `STALE_REQUEST_INPUT`, `REQUEST_FINGERPRINT_MISMATCH`, `INVALID_REQUEST_INPUT`, `SUBMISSION_STATUS_UNKNOWN`, `REQUEST_PENDING`, `REQUEST_STATUS_UNKNOWN`, `ATTEMPT_LIMIT_REACHED` |
| Budget and credentials | `FAL_KEY_MISSING`, `PRICE_NOT_VERIFIABLE`, `PRICE_STALE`, `BUDGET_WORST_CASE_EXCEEDED` |
| Results and QA | `RESULT_SAVED`, `REQUEST_FAILED`, `RESULT_RETRIEVAL_FAILED`, `RESULT_NOT_PNG`, `RESULT_URL_NOT_ALLOWED`, `EMPTY_ALPHA`, `NORMALIZED_SUBJECT_OUT_OF_BOUNDS`, `ACCEPTED_FRAME_COUNT_MISMATCH`, `DUPLICATE_FRAME_HASH`, `LOOP_CLOSURE`, `TECHNICAL_REJECTED` |

`assemble` requires all eight accepted frames, the complete five-group QA
schema, nonempty request-bound attempts, matching hashes/dimensions and a
passing QA recomputation from each confined raw result. A repeated `assemble`
on `READY_FOR_VISUAL_REVIEW` revalidates frame and review-artifact provenance;
each attempt/report fingerprint must be valid and equal the exact historical
completed request selected by request ID, attempt, frame, model and raw result.
It does not trust the previously stored global report. It writes
`normalized/Ogre_Walk_S_8f_256x416.png`,
`previews/contact_sheet.png`, `previews/loop.gif`,
`reports/consistency_report.json` and `reports/qa_report.json`, then stops at
`READY_FOR_VISUAL_REVIEW`.
