# Public roadmap

This roadmap is based on development records reviewed on 26 October 2026. Entries are not release promises. “Documented” means present in the inspected project instructions or records; it does not replace a fresh test of a frozen publication snapshot.

## Existing documented foundation

- Character PNG plus action, direction, and timing as the user-facing request.
- Provider-backed sheet and video workflows, with limited native alternatives.
- Sprite frames, sheets, previews, and artifact-bound review.
- Shared task-budget bookkeeping and known-job recovery.
- Body-reference horizontal alignment that preserves vertical motion.
- Eleven approved historical deliveries in a twelve-animation exercise.

## Milestone 1 — Reviewable public alpha

- [x] Confirm repository owner and public repository name.
- [x] Confirm code ownership and choose the code license.
- [x] Freeze an isolated source snapshot without changing the installed skill.
- [x] Review every included file for credentials, personal paths, private records, third-party notices, and redistribution restrictions.
- [x] Classify required fixtures versus development-only data; do not remove a required fixture silently.
- [ ] Add a public visual example with a documented redistribution basis. Private artwork is excluded from the initial release.
- [x] Reproduce dependency setup and selected offline tests from the isolated copy; verify a clean Git clone.
- [x] Replace draft installation text with verified instructions.
- [x] Publish English and Spanish documentation, contribution guidance, and issue templates.
- [x] Record the exact snapshot, test environment, results, limitations, and release date.

Completion: a third party can understand the scope, run the documented offline checks, and submit a useful report without access to the maintainer's machine or private artifacts.

## Milestone 2 — Close the outstanding quality case

- [ ] Resolve the golem run or publish the exact remaining failure as an open issue.
- [ ] Review the whole motion, anatomy, materials, equipment scale, frame boundaries, and loop.
- [ ] Confirm horizontal body alignment without removing vertical bounce.
- [ ] Recheck the twelve-case matrix against explicitly stated review criteria.
- [ ] Separate historical approvals from results verified under the current policy.

Completion: evidence supports the stated outcome for each of the twelve cases. Technical tests alone cannot close this milestone.

## Milestone 3 — Independent evaluation

- [ ] Build a small, licensed evaluation set with new characters not used to tune the workflow.
- [ ] Include different anatomies, long or asymmetric equipment, transparent details, and varied resolutions.
- [ ] Record action, route, provider, cost estimate, visual criteria, and failure reasons.
- [ ] Distinguish reproducible technical checks from human or agent visual judgments.
- [ ] Publish limitations and representative failures alongside successes.

Completion: a reader can inspect what was tested, reproduce the protocol where provider access permits, and understand what remains unknown.

## Milestone 4 — Contributor experience

- [ ] Validate installation on a clean Windows environment.
- [ ] Investigate Linux and macOS support through actual checks.
- [ ] Identify a short, deterministic offline test set.
- [ ] Keep network or paid tests opt-in and separate from ordinary contributions.
- [ ] Document the main entry points and the boundary between current, legacy, and experimental workflows.
- [ ] Add narrowly scoped starter issues after checking the relevant code.

## Candidate contribution topics

These are candidate topics; issue creation and implementation remain separate:

- Reproduce the setup guide on a clean machine.
- Supply a small evaluation image with clear redistribution permission.
- Improve an ambiguous review criterion with a concrete failure example.
- Add a regression for a confirmed scale, alignment, alpha, or recovery defect.
- Improve English/Spanish documentation consistency.

Provider changes and new models should be evaluated against a concrete defect and a budget. Adding more integrations is not the initial goal.
